Function Standalone

A standalone block of code, called by name. The data is passed into it as an argument. Functions live in the global/builtin namespace and work on many types.

len(my_list) # builtin function, data passed in sorted(my_list) sum([1, 2, 3])

Method Bound to Object

A function attached to a specific object/type, called via dot notation. The object itself is the implicit first argument (self) and may mutate the object in place.

my_list.append(42) # method, object owns the call my_str.upper() my_dict.keys()
01

NoneType

The presence of absence — exactly one singleton value: None

None — the singleton null value
Immutable · Singleton

Core distinction: None is the only instance of NoneType. It represents "no value here" — used for missing data, default parameters, and as the implicit return of functions that don't explicitly return. Always compare with is None, never == None.

5 Real-World Examples

# 1) Sentinel for "no result" from a function
def find_user(user_id):
    if user_id not in database:
        return None
    return database[user_id]

result = find_user(999)
if result is None:
    print("User not found")
# User not found
# 2) Default parameter value (mutable-default avoidance)
def append_item(item, target=None):
    if target is None:
        target = []          # fresh list each call
    target.append(item)
    return target

print(append_item(1))   # [1]
print(append_item(2))   # [2]   -- NOT [1, 2]
# 3) Placeholder while building a structure
user = {"name": "Ada", "email": None}
# email collected later in the form flow
user["email"] = "ada@example.com"
print(user)
# {'name': 'Ada', 'email': 'ada@example.com'}
# 4) Discarding a function's return value explicitly
def log(msg):
    print("[LOG]", msg)
    # no return -> implicitly returns None

outcome = log("booting up")
print(outcome is None)
# True
# 5) Clearing a variable's reference without deleting it
cache = {"a": 1, "b": 2}
cache = None          # release reference, allow GC
print(type(cache))
# <class 'NoneType'>
print(bool(cache))
# False   (None is falsy)

Functions vs Methods

bool(None)→ False (None is falsy) (none)NoneType intentionally exposes zero methods — it has no behaviour to invoke.
type(None)→ <class 'NoneType'> (none)All interaction happens via operators and built-ins, not methods.
id(None)Always returns the same id — singleton (none)
print(None)→ prints "None" (none)
str(None)→ "None" (string form) (none)
02

Single Value Data Types

Scalars — each object holds exactly one atomic value at a time.

int — arbitrary-precision integer
Immutable

Core distinction: Whole numbers with no size limit (Python 3 auto-promotes beyond 64 bits). Use for counting, indexing, IDs, and exact integer math. No overflow — only your RAM limits you.

5 Real-World Examples

# 1) Basic arithmetic with operator precedence
total = 7 + 3 * 2      # 13, not 20
remainder = 17 % 5    # 2  (modulo)
power = 2 ** 10       # 1024
print(total, remainder, power)
# 13 2 1024
# 2) Arbitrary precision -- no overflow ever
big = 2 ** 100
print(big)
# 1267650600228229401496703205376
print(big * big)
# 1606938044258990275541962092341162602522202993782792835301376
# 3) Parsing strings to int with a base
decimal = int("255")          # 255 (base 10)
binary  = int("11111111", 2)  # 255 (base 2)
hexnum  = int("ff", 16)        # 255 (base 16)
print(decimal, binary, hexnum)
# 255 255 255
# 4) Floor division and divmod for splitting
cookies = 23
kids = 4
each, leftover = divmod(cookies, kids)
print(f"Each gets {each}, leftover {leftover}")
# Each gets 5, leftover 3
# 5) Bitwise operations on flags
READ, WRITE, EXEC = 1, 2, 4
perm = READ | WRITE          # 3
can_write = bool(perm & WRITE) # True
print(bin(perm), can_write)
# 0b11 True
print((255).bit_count())   # 8 ones in binary

float — IEEE-754 double precision
Immutable

Core distinction: 64-bit floating point (≈15-17 significant digits). Use for measurements, scientific math, fractions. Carries rounding artefacts — never use == on floats, use math.isclose.

5 Real-World Examples

# 1) Fractional arithmetic -- note rounding artefacts
print(0.1 + 0.2)
# 0.30000000000000004   (NOT 0.3!)
import math
print(math.isclose(0.1 + 0.2, 0.3))
# True   (correct way to compare floats)
# 2) Scientific notation for huge / tiny numbers
speed_of_light = 2.998e8      # m/s  == 299_800_000.0
planck = 6.626e-34          # J·s  == 0.000...06626
print(speed_of_light, planck)
# 299800000.0 6.626e-34
# 3) Special values: infinity and NaN
inf = float("inf")
nan = float("nan")
print(inf > 10**100)       # True
print(nan == nan)           # False  (NaN is never equal to itself)
print(math.isnan(nan))       # True
# 4) Rounding for display / currency
price = 19.995
print(round(price, 2))         # 20.0   (banker's rounding)
print(round(2.5), round(3.5))     # 2 4    (rounds to even)
# For money, use Decimal, not float:
from decimal import Decimal
print(Decimal("19.995").quantize(Decimal("0.01")))  # 20.00
# 5) Float construction from fraction or string
from fractions import Fraction
print(float(Fraction(1, 3)))    # 0.3333333333333333
print(float("3.14"))           # 3.14
print((3.14).as_integer_ratio())
# (7070651414971679, 2251799813685248)
print((5.0).is_integer())        # True

complex — real + imaginary (j)
Immutable

Core distinction: Pairs a real and imaginary float, written a + bj. Use for signal processing, electrical engineering (impedance), quantum mechanics, and 2D rotation. Python uses j, not i.

5 Real-World Examples

# 1) Creating complex numbers three ways
z1 = 3 + 4j              # literal
z2 = complex(3, 4)       # constructor
z3 = complex("3+4j")       # from string
print(z1, z2, z3, z1 == z2 == z3)
# (3+4j) (3+4j) (3+4j) True
# 2) Accessing real and imaginary parts
z = 5 - 2j
print(z.real, type(z.real))    # 5.0 <class 'float'>
print(z.imag, type(z.imag))    # -2.0 <class 'float'>
print(abs(z))                 # |z| = sqrt(5^2 + 2^2)
# 5.385164807134504
# 3) Arithmetic: addition & multiplication behave geometrically
a = 1 + 1j
b = 1 - 1j
print(a + b)               # 2+0j  (vector add)
print(a * b)               # 2+0j  (|a|*|b| since b = conj(a))
print(a.conjugate())       # 1-1j  (flips imaginary sign)
# 4) Electrical impedance: Z = R + jX
resistor = 100 + 0j         # pure resistor
inductor = 0 + 50j           # X_L = +50 ohm
capacitor = 0 - 30j          # X_C = -30 ohm
total_impedance = resistor + inductor + capacitor
print(total_impedance)
# (100+20j)
print(abs(total_impedance))   # ~101.98 ohm
# 5) 2D rotation as complex multiplication
import math
point = 1 + 0j                  # point at (1, 0)
angle = math.radians(90)        # rotate 90°
rotator = complex(math.cos(angle), math.sin(angle))
rotated = point * rotator
print(rotated)
# (6.12e-17+1j)  ≈ 0+1j  → point moved to (0, 1)

bool — True / False (subclass of int)
Immutable

Core distinction: A subclass of int — True == 1 and False == 0 both hold. Use for flags, conditions, and any "yes/no" state. Every value in Python is truthy or falsy via bool().

5 Real-World Examples

# 1) Comparisons return bool objects
print(5 > 3, 5 == 5, 5 != 5)
# True True False
print(type(5 > 3))
# <class 'bool'>
print(issubclass(bool, int))
# True   -- bool IS an int
# 2) Logical operators: and, or, not
is_admin = True
is_active = False
can_login = is_active and is_admin     # False
can_reset = is_admin or is_active       # True
blocked = not is_active                 # True
print(can_login, can_reset, blocked)
# False True True
# 3) bool() of any value -- the truthiness rule
print(bool(0), bool(0.0), bool(""), bool([]), bool({}), bool(None))
# False False False False False False   (all "empty" → False)
print(bool(1), bool("hi"), bool([0]), bool("False"))
# True True True True  (non-empty → True, even "False" the string!)
# 4) True/False as integers in arithmetic (footgun!)
sales = [100, 0, 250, 0, 80# Count non-zero sales using bool sum trick:
non_zero_count = sum(bool(s) for s in sales)
print(non_zero_count)
# 3   (True = 1 added three times)
print(True + True + True)
# 3
# 5) Feature flags & conditional dispatch
feature_flags = {
    "dark_mode": True,
    "beta_ui":   False,
    "analytics": True,
}
if feature_flags["dark_mode"]:
    theme = "dark"
else:
    theme = "light"
print(theme)
# dark

03

Multiple Value Data Types

Collections — one object holding many values, in various shapes (ordered / unordered, mutable / immutable).

str — immutable Unicode text
Immutable · Ordered · Iterable

Core distinction: An immutable sequence of Unicode code points. Every "edit" produces a new string. Use for any text — names, logs, JSON, regex. Python 3 strings are fully Unicode by default.

5 Real-World Examples

# 1) Creation: single, double, triple-quoted strings
name = 'Ada Lovelace'
greeting = "It's alive!"          # double to embed apostrophe
poem = """Roses are red,
Violets are blue,
Python is awesome,
And so are you."""
print(poem.count("\n"))
# 3
# 2) Slicing & indexing (str IS a sequence)
url = "https://example.com"
print(url[0:5])        # 'https'
print(url[-4:])        # '.com'
print(url[::-1])       # 'moc.elpmaxe//:sptth' (reversed)
print(len(url))         # 19
# 3) f-string formatting (Python 3.6+)
user = "Marie"
score = 98.6
msg = f"User {user!r} scored {score:.1f} points"
print(msg)
# User 'Marie' scored 98.6 points
# !r forces repr, :.1f formats float
# 4) Common text transformations
raw = "  Hello, World!  "
clean = raw.strip()                 # 'Hello, World!'
upper = clean.upper()               # 'HELLO, WORLD!'
words = clean.split(", ")           # ['Hello', 'World!']
joined = "-".join(words)            # 'Hello-World!'
replaced = clean.replace("World", "Python")
print(replaced)
# Hello, Python!
# 5) Unicode handling -- emojis & non-ASCII
emoji = "Python 🐍"
print(len(emoji))            # 8  (7 ASCII chars + 1 emoji code point)
print(emoji[-1>])              # 🐍
print(ord("A"), ord("🐍"))       # 65 128013
print(chr(128013))            # 🐍

list — mutable ordered sequence
Mutable · Ordered · Iterable

Core distinction: The workhorse ordered collection — append, insert, remove, sort in place. Use for stacks, queues, accumulators, anything that grows/shrinks. O(1) append/pop from the end.

5 Real-World Examples

# 1) Creation: literals, constructors, comprehensions
nums = [1, 2, 3]
from_range = list(range(5))          # [0, 1, 2, 3, 4]
mixed = [1, "two", 3.0, [4]]     # heterogeneous OK
squares = [x*x for x in range(5)]    # [0, 1, 4, 9, 16]
print(nums, from_range, mixed, squares)
# 2) Mutation: append, insert, extend, pop, remove
todo = ["buy milk", "walk dog"]
todo.append("pay bills")           # end
todo.insert(0, "wake up")           # at index 0
todo.extend(["code", "sleep"])        # merge
last = todo.pop()                   # 'sleep'
todo.remove("walk dog")             # by value
print(todo)
# ['wake up', 'buy milk', 'pay bills', 'code']
# 3) Slicing returns a NEW list (copy)
orig = [10, 20, 30, 40, 50
copy = orig[:]                     # shallow copy
middle = orig[1:4]                 # [20, 30, 40]
every_other = orig[::2]            # [10, 30, 50]
rev = orig[::-1]                  # [50, 40, 30, 20, 10]
orig[0:2] = [99, 98]               # slice assignment
print(orig)
# [99, 98, 30, 40, 50]
# 4) Sorting & reversing -- in place vs new
nums = [3, 1, 4, 1, 5, 9, 2, 6]
nums.sort()                        # in place, returns None
print(nums)
# [1, 1, 2, 3, 4, 5, 6, 9]
nums.sort(reverse=True)
print(nums)
# [9, 6, 5, 4, 3, 2, 1, 1]
# sorted() is the FUNCTION version -- returns new list:
words = ["banana", "apple", "cherry"]
print(sorted(words, key=len))
# ['apple', 'banana', 'cherry']
# 5) Stacking & queueing patterns
stack = []
stack.append("page1")
stack.append("page2")
print(stack.pop())              # 'page2'  (LIFO)
# For queues, use collections.deque (O(1) popleft):
from collections import deque
queue = deque(["a", "b"])
queue.append("c")
print(queue.popleft())         # 'a'  (FIFO)
print(list(queue))            # ['b', 'c']

tuple — immutable ordered sequence
Immutable · Ordered · Hashable

Core distinction: Like a list, but you cannot change it after creation. Use for fixed records, multi-return, dict keys, and protecting data from accidental mutation. Slightly faster and lighter than list.

5 Real-World Examples

# 1) Creation -- note the trailing comma for singletons
empty = ()
single = (42,)            # COMMA is required! (42) is just an int
multi = (1, 2, 3)
no_parens = 1, 2, 3      # parens optional
from_list = tuple([4, 5, 6])
print(single, multi, no_parens, from_list)
# (42,) (1, 2, 3) (1, 2, 3) (4, 5, 6)
# 2) Packing & unpacking (the canonical use case)
point = (3, 4)             # packing
x, y = point                 # unpacking
print(x, y)                 # 3 4
# Swap two values without a temp variable:
a, b = 10, 20
a, b = b, a
print(a, b)                 # 20 10
# 3) Returning multiple values from a function
def min_max(numbers):
    return min(numbers), max(numbers)   # implicit tuple
lo, hi = min_max([3, 7, 1, 9, 2])
print(f"min={lo}, max={hi}")
# min=1, max=9
# Catch-all unpacking with *:
first, *rest = (1, 2, 3, 4, 5)
print(first, rest)         # 1 [2, 3, 4, 5]
# 4) Used as dict keys (lists CANNOT do this!)
locations = {
    (40.7128, -74.0060): "New York",
    (34.0522, -118.2437): "Los Angeles",
    (51.5074, -0.1278): "London",
}
print(locations[(40.7128, -74.0060)])
# New York
# Why? Tuples are hashable; lists are not (mutable).
# 5) Named tuples for self-documenting records
from collections import namedtuple
Point = namedtuple("Point", ["x", "y"])
p = Point(3, 4)
print(p.x, p.y)             # 3 4  (access by name!)
print(p[0], p[1])            # 3 4  (still indexable)
print(p._asdict())          # {'x': 3, 'y': 4}
# Immutability means no p.x = 5 --> AttributeError

set — mutable unordered unique collection
Mutable · Unordered · Unique

Core distinction: Holds only unique, hashable elements with no defined order. O(1) membership tests. Use for deduplication and set-theory math (union, intersection, difference).

5 Real-World Examples

# 1) Deduplication -- the killer use case
visitors = ["alice", "bob", "alice", "carol", "bob"]
unique_visitors = set(visitors)
print(unique_visitors)
# {'alice', 'bob', 'carol'}   (order not guaranteed)
print(len(unique_visitors))
# 3
# 2) O(1) membership testing vs O(n) for lists
valid_codes = {"X-100", "X-200", "X-300"}
user_input = "X-200"
if user_input in valid_codes:        # fast even for millions of codes
    print("Valid!")
# Valid!
# Empty set MUST use set() -- {} is a dict!
empty = set()
print(type(empty))             # <class 'set'>
# 3) Set operations: union, intersection, difference
frontend = {"Alice", "Bob", "Carol"}
backend  = {"Bob", "Dave", "Eve"}
print(frontend | backend)    # union: {'Alice','Bob','Carol','Dave','Eve'}
print(frontend & backend)     # intersection: {'Bob'}
print(frontend - backend)    # difference: {'Alice', 'Carol'}
print(frontend ^ backend)    # symmetric diff: {'Alice','Carol','Dave','Eve'}
# 4) Mutation: add, remove, discard, update
tags = {"python", "web"}
tags.add("backend")             # add single
tags.update(["api", "docker"])     # add many
tags.discard("web")              # remove, no error if missing
# tags.remove("not_there")  # WOULD raise KeyError
popped = tags.pop()                # arbitrary element removed
print(tags, "popped:", popped)
# 5) frozenset -- the immutable cousin (hashable!)
fs = frozenset([1, 2, 3])
# fs.add(4)  --> AttributeError (immutable)
# Can be used as dict key or set element:
graph = {
    frozenset({"a", "b"}): "edge1",
    frozenset({"b", "c"}): "edge2",
}
print(graph[frozenset({"b", "a"})])   # 'edge1' (order-insensitive!)
print({1, 2, 3} >= {1, 2})               # True  (superset check)

dict — mutable key→value mapping
Mutable · Ordered (3.7+) · Hashable Keys

Core distinction: Maps hashable keys to arbitrary values, with O(1) lookup by key. Since Python 3.7, insertion order is preserved. Use for labelled data, caches, configs, JSON — the most-used collection in Python.

5 Real-World Examples

# 1) Three creation styles
literal = {"name": "Ada", "age": 36}
constructor = dict(name="Ada", age=36)
from_pairs = dict([("name", "Ada"), ("age", 36)])
print(literal == constructor == from_pairs)
# True
# Insertion order IS preserved (Python 3.7+):
print(list(literal.keys()))
# ['name', 'age']
# 2) Access: [] vs .get() vs setdefault()
user = {"name": "Ada", "email": "ada@x.com"}
print(user["name"])              # 'Ada'
# user["phone"]  --> KeyError! Use .get instead:
print(user.get("phone"))         # None
print(user.get("phone", "N/A"))   # 'N/A'  (default)
# setdefault: get-or-insert in one step:
user.setdefault("phone", []).append("555-0100")
print(user["phone"])            # ['555-0100']
# 3) Iteration: keys, values, items
prices = {"apple": 1.20, "banana": 0.50, "cherry": 3.00}
for fruit in prices:              # iterates keys by default
    print(fruit, end=" ")
# apple banana cherry
for fruit, price in prices.items():   # unpacked pairs
    print(f"{fruit}: ${price:.2f}")
total = sum(prices.values())
print(f"Total: ${total:.2f}")
# Total: $4.70
# 4) Update, merge, and pop
defaults = {"theme": "light", "lang": "en", "tz": "UTC"}
user_prefs = {"theme": "dark", "lang": "fr"}
defaults.update(user_prefs)        # in-place merge
print(defaults)
# {'theme': 'dark', 'lang': 'fr', 'tz': 'UTC'}
removed = defaults.pop("tz")        # 'UTC'
last = defaults.popitem()          # removes last inserted (LIFO)
# Python 3.9+ merge operator | :
merged = {"a": 1} | {"b": 2}
print(merged)                   # {'a': 1, 'b': 2}
# 5) Dict comprehension & nested dicts
nums = [1, 2, 3, 4, 5]
squares = {n: n*n for n in nums}
print(squares)
# {1: 1, 2: 4, 3: 9, 4: 16, 5: 25}
# Invert a dict (values must be unique):
inverted = {v: k for k, v in squares.items()}
print(inverted[25])              # 5
# Nested: dict-of-dicts (think JSON)
company = {
    "engineering": {"headcount": 12, "budget": 1_000_000},
    "sales":       {"headcount": 5,  "budget": 500_000},
}
print(company["engineering"]["budget"])
# 1000000
